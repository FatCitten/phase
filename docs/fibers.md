# Fibers

Fibers are intentionally closer to OS processes than agent personas.

A fiber has an objective, dependency set, execution backend, capability set, resource frame, state mapping, validation gate, and terminal outcome. Phase can later add fork/join/retry semantics without changing the idea that a fiber is a bounded unit of allocated cognition.

CLI percentages represent lifecycle state only. Phase never invents "74% of implementation finished" from model intuition.
